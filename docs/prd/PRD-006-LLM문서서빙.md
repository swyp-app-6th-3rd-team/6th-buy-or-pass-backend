# PRD-006 — LLM 문서 서빙 (llms.txt)

## 무엇을 왜

FE 개발자가 바이브 코딩 워크플로우를 돌릴 때 API 계약을 LLM 프롬프트에 붙여넣는다.
그런데 기존 문서 표면 셋은 모두 **사람이 브라우저로 읽는 것**을 전제한다 —
Swagger UI 와 Scalar 는 긁으면 마크업이 딸려오고, `/v3/api-docs` 는 `$ref` 로 정규화돼
스키마가 흩어진 채 토큰만 비싸다.

문서를 손으로 따로 관리하면 그 순간부터 코드와 어긋난다.
그래서 이 사이클의 제1 요구사항은 포맷이 아니라 **드리프트가 구조적으로 불가능할 것**이다.
springdoc 이 이미 만들어 둔 OpenAPI 를 런타임에 읽어 마크다운으로 옮기기만 한다.

결정 근거: [ADR-0011](../adr/0011-llms-txt-runtime-rendering.md)

## 범위

### 포함

- `GET /llms.txt` — springdoc 스펙을 LLM 친화 마크다운으로 렌더 (`text/plain;charset=UTF-8`)
- `GET /llms.md` — 같은 본문의 별칭
- `$ref` 인라인 전개 — 순환 참조 가드(visited 백트래킹) + 깊이 상한 이중 방어
- `ApiResponse` 봉투를 머리말에 한 번만 적고 `returnObject` 안쪽만 렌더
- `SecurityConfig.PUBLIC_GET` 에 문서 경로 추가 (인증 없이 접근)
- `OpenAPI` 빈으로 스펙 제목·버전 지정 (Swagger UI·Scalar 에도 함께 반영)

### 제외 (사유 포함)

| 제외 | 사유 |
|---|---|
| 태그별 분할 엔드포인트 `/llms/{tag}.md` | `paths-to-match: /api/**` 라 현재 스펙이 **태그 1개·오퍼레이션 3개**다. 전체 문서와 사실상 같은 것을 위해 라우트·슬러그 정규화·404 를 지는 건 측정 없는 최적화. 렌더러에 `render(oas, tag)` 오버로드만 만들어 두고 라우트는 노출하지 않는다 |
| 빌드타임 정적 파일 굽기 | 빌드가 앱 기동에 의존해 느려지고, 로컬에서 재기동해도 파일이 안 바뀌어 드리프트가 되살아난다 |
| 오퍼레이션별 인증 여부 표시 | `SecurityScheme` 빈이 없어 스펙의 `operation.security` 가 비어 있다. 없는 메타데이터를 지어내면 그게 이 기능이 막으려는 드리프트다. 머리말에 전역으로만 적는다 |
| `ResponseCode` 에러 카탈로그 전량 수록 | 스펙에 잡히지 않는다. 렌더러에 손으로 베끼면 같은 이유로 드리프트가 된다 |
| 응답 캐싱 | 측정 없이 최적화하지 않는다. `/v3/api-docs` 도 매 요청 생성이고 문서 경로는 호출 빈도가 낮다 |

## 완료 판정

**대리지표로 완료를 선언하지 않는다** — 빌드 성공·테스트 통과는 실패 판정용으로만 쓴다.
아래는 실제 기동(`bootRun` + MySQL) 후 측정한 값이다.

| # | 판정 기준 | 결과 |
|---|---|---|
| 1 | 스펙의 오퍼레이션 수와 문서의 오퍼레이션 수가 같다 | ☑ **스펙 3 / 문서 3** 일치 |
| 2 | 인증 헤더 없이 `/llms.txt` 가 200 이다 | ☑ 200 (`PUBLIC_GET` 반영) |
| 3 | 인증이 필요한 API 는 여전히 401 이다 (과다 개방 없음) | ☑ `/api/auth/me` → **401** |
| 4 | `Content-Type` 이 `text/plain` 이라 브라우저가 다운로드하지 않는다 | ☑ `text/plain;charset=UTF-8`, 브라우저 `Accept` 헤더로도 200 (406 아님) |
| 5 | `/llms.md` 가 `/llms.txt` 와 동일 본문이다 | ☑ `diff` 차이 없음 |
| 6 | `$ref` 가 인라인 전개된다 | ☑ `MeResponse`·`TokenResponse` 필드가 펼쳐져 출력 |
| 7 | 순환 참조에서 `StackOverflowError` 없이 유한 시간에 끝난다 | ☑ 자기참조·상호순환·깊이초과 3종 테스트 통과. **가드 제거 시 실제로 `StackOverflowError` 발생을 먼저 확인**한 뒤 가드 추가 |
| 8 | 다이아몬드 참조를 순환으로 오인하지 않는다 | ☑ `billing`·`shipping` 이 둘 다 `Address` 를 참조할 때 양쪽 전개 확인 |
| 9 | **컨트롤러를 고치면 렌더러 코드 변경 0 으로 문서가 따라온다** | ☑ `@Operation(summary)` 한 줄 수정 후 재기동 → 출력 반영 확인 (이 기능의 존재 이유) |
| 10 | 기존 문서 표면에 회귀가 없다 | ☑ `/v3/api-docs` 200 · `/swagger-ui.html` 302 · `/scalar` 200 |
| 11 | 전체 테스트 통과 | ☑ **87건 / 실패 0** |
| 12 | 아키텍처 규칙 위반 없음 | ☑ `ArchitectureTest` 18 규칙 통과 (생성자 주입 준수) |

## 열린 질문

- **`springdoc.paths-to-match: /api/**` 가 장기 의도인가?** 현재 스펙에 3개만 잡히는 이유다.
  도메인 API 가 붙기 시작하면 이 범위가 맞는지 재확인이 필요하다.
- **`SecurityScheme` 빈을 추가할 것인가?** 추가하면 Swagger UI·Scalar·`/llms.txt` 가
  동시에 오퍼레이션별 인증 표시를 얻는다. 다만 별개 관심사라 이번 범위에서 분리했다.
- **운영에서 문서 경로를 잠글 것인가?** 잠근다면 `/llms.txt` 도 함께 잠겨야 한다.
  `PUBLIC_GET` 의 같은 자리에 넣어 갈라질 수 없게 해 두었다.

## 알려진 선행 이슈 (이번 범위 밖)

- `docs/SPEC.md` 2절이 `rental/`·`sakila/` 패키지를 기술하나 `src/` 에 실재하지 않는다.
  7절의 "108건 통과"도 현재는 87건이다. 삭제가 의도된 정리인지 판단할 근거가 없어 건드리지 않았다.
- 통합 테스트가 `withReuse(true)` 로 MySQL 컨테이너를 재사용하는데, 오래된 컨테이너가
  옛 `V1` 체크섬을 들고 있으면 **Flyway checksum mismatch 로 전 통합 테스트가 실패**한다.
  이번에 실제로 발생했고 컨테이너 제거로 해소했다(코드 문제 아님).
  재발 시 `docker rm -f $(docker ps -aq --filter label=org.testcontainers=true)`.
